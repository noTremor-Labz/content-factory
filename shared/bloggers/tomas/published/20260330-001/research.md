## 1. Что такое мультиагентный контент-завод

**Концепция:**  
Мультиагентный контент-завод — это система, где вместо одного универсального AI-инструмента работает команда специализированных агентов. Каждый делает своё: один ресёрчит, другой пишет, третий редактирует, четвёртый публикует. Как редакция, только без людей (почти).

**Метафора для поста:**  
Представь настоящую редакцию — шеф-редактор, репортёры, копирайтеры, дизайнеры, SMM. Теперь замени каждого на AI-агента. Они не спят, не выгорают, не просят повышения. Это и есть контент-завод.

**Зачем нужен:**
- Контент — топливо для роста. 3М показов в X, 500 подписчиков, охваты в Telegram — всё это требует стабильного потока постов
- Один LLM (даже GPT-4) быстро теряет контекст на длинном пайплайне: план → идея → драфт → редактура
- Нет специализации — нет качества. Один агент не может одновременно думать как стратег и писать как копирайтер
- Автоматизация ≠ клонирование. Грамотная система сохраняет голос автора, но снимает 80% рутины

**Реальность 2025 (без розовых очков):**  
vc.ru отмечает: «Без человеческого контроля контент-производство буксует». Заводы работают, но "наблюдатель" всё равно нужен. Это не волшебная кнопка — это инструмент.

## 2. Ключевые шаги настройки

### Шаг 1: Определить роли агентов

Классический стек (по опыту из продакшн-систем):

| Агент | Роль | Инструменты |
|-------|------|-------------|
| **Scout / Researcher** | Ресёрч трендов, сбор инфы | Web search, RSS, Hacker News |
| **Strategist / Planner** | Контент-план, распределение по воронке | Профиль аудитории, цели |
| **Ideation Agent** | Генерация хуков, форматов | Творческие промпты |
| **Quill / Writer** | Написание драфта | Голос блогера, бриф |
| **Lens / Editor** | Редактура, факт-чек, качество | Гайдлайны бренда |
| **Pixel / Visual** | Промпты для изображений | Imagen, Midjourney |
| **Launch / Publisher** | Публикация в каналы | API платформ |
| **Director** | Оркестратор — раздаёт задачи, контролирует | Все выше |

### Шаг 2: Спроектировать пайплайн

```
Входящая задача
     ↓
Director (получает тему/формат/платформу)
     ↓
Scout → research.md
     ↓
Writer → draft_v1.md
     ↓
Editor → APPROVE / REJECT (не > 2 итераций)
     ↓ (при APPROVE)
Visual → image_prompt.txt
     ↓
Publisher → пост улетел
```

**Ключевой принцип:** каждый агент работает с файлами/папками job-а, не передаёт данные напрямую. Это изоляция и трассируемость.

### Шаг 3: Выбрать инструменты оркестрации

**Варианты:**
- **OpenAI Agents SDK** — для тех, кто на GPT-экосистеме, встроенный handoff между агентами
- **LangGraph** — state machine, хорош для сложных граф-пайплайнов с retry
- **n8n** — no-code/low-code оркестратор, визуальный, можно без кода
- **Dify** — визуальный конструктор, open source, хорошо для старта
- **OpenClaw (custom)** — полная кастомизация через субагентов, как у нас

**Модели по ролям:**
- Research + Planning → GPT-4o / Claude Sonnet (нужен интеллект)
- Writing → Claude Sonnet / GPT-4o (качество текста)
- Editing / QA → Claude (строгость)
- Visual prompts → GPT-4o / Gemini
- Budget-оптимизация → GPT-4o mini для рутинных задач ($0.15–0.30 за пост реально)

### Шаг 4: Задать контекст агентам (самое важное!)

Без контекста агенты пишут "в пустоту". Нужно:
- **Brand voice doc** — как звучит блогер, примеры постов, запрещённые фразы
- **Audience profile** — кто читает, что их цепляет
- **Visual style guide** — цвета, настроение, референсы
- **Job folder** — изолированная папка для каждого поста (research.md, draft_v1.md, image_prompt.txt)

### Шаг 5: Добавить человека в петлю

Не убирай себя полностью. Точки контроля:
- После Draft (можно скипнуть при доверии к системе)
- После редактуры Editor-а — финальное "APPROVE / REJECT"
- Перед публикацией — особенно для чувствительных тем

## 3. Практические примеры, боли, инсайты

### Реальные архитектуры

**3-агентная система (из Medium, catsmice):**
- Curator — фильтрует новости, ищет трендовый контент
- Creator — пишет под платформу (FB, Instagram, Twitter)
- Critic — оценивает по 6 параметрам качества, выдаёт APPROVE/REJECT
- Оркестрация через LangGraph

**9-агентная система (Google Cloud, production):**
- Research → Content Generator → Editor → SEO Optimizer → QA → Image Generator → Video → Audio → Publisher
- Google Cloud + Vertex AI + Gemini
- Стоимость: $0.15–0.30 за материал
- 60%+ cache hit rate (кэш = экономия)
- 99.9% uptime

**Multi-agent pipeline (Valentin Chmara, X/Twitter):**
- Profile Agent анализирует топ-посты и аудиторию
- Trend Agent ищет актуальные темы (Hacker News, web)
- Planning Agent → 15–25 слотов в неделю (TOFU/MOFU/BOFU)
- Ideation → Writing → CCO Review
- Результат: контент съедал 50% времени → освободил

### Боли и грабли

🔥 **"Один LLM не может всё"** — пробовал один промпт на всё? Получается каша. Специализация — это не лишняя сложность, это необходимость.

🔥 **Контекст теряется** — длинный пайплайн без State Management = агент к шагу 4 забыл, что писал на шаге 1. Решение: общий job-файл с брифом + state в LangGraph/OpenClaw.

🔥 **"Звучит не как я"** — самая частая жалоба. Решение: brand voice doc, примеры постов в промпте, итеративное обучение редактора под голос.

🔥 **Петли reject** — Editor реджектит, Writer переписывает, Editor снова реджектит... Правило: не более 2 итераций, потом эскалация человеку.

🔥 **Стоимость без кэша** — без оптимизации API-запросы взлетают. Cache-слой + бюджетный контроллер обязательны в продакшне.

🔥 **"Завод стоит"** — один упавший агент останавливает весь пайплайн. Нужны retry, timeout, алерты.

### Инсайты

💡 Агенты работают лучше всего, когда у них **чёткая роль и ограниченный scope**. Не "напиши пост", а "напиши intro-параграф в стиле [voice] на основе [research.md], 150 слов".

💡 **Файловая система как shared memory** — агенты не должны разговаривать напрямую. Job-папка с файлами — это трассируемость, дебаг, возможность откатиться.

💡 **Director = мозг системы** — он не пишет контент, он маршрутизирует, следит за статусом, эскалирует. Классический паттерн "Orchestrator + Subagents".

💡 **Начинай с малого** — 3 агента лучше, чем 9, если ты только начинаешь. Добавляй агентов по мере того, как видишь узкие места.

## 4. Тон для Telegram-канала — vibe-стиль

**Подход к посту:**
- От первого лица: "я строил", "я облажался", "я понял"
- Без академизма: не "мультиагентная архитектура", а "команда AI-роботов"
- С конкретикой: цифры, инструменты, реальные имена агентов
- Честно про боли: "первые 3 дня были провалом"
- Хуки через контраст: "думал, нажму кнопку и всё. Не нажал."

**Примеры вводных фраз для поста:**
- "Полгода назад я попробовал автоматизировать весь контент. Вот что из этого вышло."
- "Контент-завод звучит как мечта. На деле — это 3 упавших агента и один злой Editor."
- "Я нанял команду. Они не берут зарплату, не болеют и работают в 3 ночи. Это мои AI-агенты."
- "Один инструмент vs система агентов — разница как между блокнотом и редакцией."

**Структура поста (vibe-формат):**
1. Личный хук (1-2 предложения, боль или неожиданность)
2. "Раньше я делал X" (контекст и проблема)
3. "Потом я собрал систему" (решение с конкретикой)
4. Инсайт / урок
5. CTA или открытый вопрос
